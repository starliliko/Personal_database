# 工程知识

这里准备保存我在真实工作中形成的工程方法和经验。

很多问题解决以后，只剩下一句“已经修好”或一组最终参数，但真正能提高下一次效率的，是背后的判断过程：先排查什么，怎样区分不同原因，哪些现象容易误导，什么证据才足以说明问题真的解决了。

工程知识希望把这些过程提炼出来。

## 它与项目文档有什么不同

假设某架无人机出现振动：

- 项目仓库记录具体是哪架飞机、什么工况、哪个部件或参数有问题、最后怎样修复。
- 这里则总结一套可以复用的振动诊断方法：机械激励、动力系统不平衡、惯性测量安装、结构共振和控制振荡应该怎样区分，推荐排查顺序是什么，常见误判有哪些。

工程知识只引用项目里的实际案例，不复制项目文档全文。

## 准备逐步提炼的方向

目前这个目录还没有正式完成的专题。后续会从真实项目材料中逐步提炼：

- 无人机振动问题诊断；
- Jetson 环境部署与验收；
- ROS 2 工作区构建失败定位；
- 外部定位接入 PX4 的分层验证；
- 飞行日志完整性和状态估计分析；
- 客户交付文档的证据边界与验收方法。

这些题目现在只是方向，不代表已经形成结论。每篇工程知识都需要能够追溯到真实项目事实，同时清除不适合公开的设备、客户和业务信息。

## 一篇工程知识应该带走什么

读完以后，至少应该知道：

- 遇到什么现象时可以使用这套方法；
- 原因可以分成哪些类别；
- 推荐从哪里开始排查；
- 怎样快速排除错误方向；
- 需要采集什么证据；
- 哪些结论只能由对应项目文档确认。
