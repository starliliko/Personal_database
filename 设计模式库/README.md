# 设计模式库

一个具体案例可能使用 Mid-70、某款相机或某个计算平台，但这些型号未必能复用。真正值得长期保存的，往往是它背后的系统结构。

设计模式库就用来记录这些结构：它解决什么矛盾，在什么条件下成立，会带来哪些收益和代价，又会以什么方式失败。

## 当前模式

### [地面重计算与机载实时闭环](地面重计算与机载实时闭环.md)

这个模式面向尺寸、重量与功耗受限的机器人：

```text
外部重感知和重计算
          ↓
低频观测、轨迹或任务信息
          ↓
────────────────────
          ↓
本体高频状态估计和实时控制
```

它可能适用于微型无人机、小型机器人、多机器人系统和实验室环境，但会引入外部覆盖、通信延迟、时间同步和共同故障点。

目前这个模式只从 RM2027 概念案例中抽象出来，成熟度仍为 L0。只有经过更多案例和真实验证后，才能把它当成可靠的复用模式。

## 设计模式与架构决策的区别

项目中的架构决策记录说明“这个项目为什么这样选”；设计模式则回答“以后什么场景还可以考虑这种结构”。前者跟随具体项目，后者尝试跨项目复用。
