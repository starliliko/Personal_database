# 工作复盘

这个目录用来保存轻量的工作回顾，而不是再制造一份项目日报或技术文档。

一篇工作复盘只需要回答三件事：今天完成了什么，正式项目记录在哪里，以及这项工作给我留下了什么可以复用的认识。

## 推荐写法

```markdown
# YYYY-MM-DD 工作复盘

## 今天完成了什么

一句话说明工作结果。

## 项目记录

- 项目仓库规范文档：链接

## 个人沉淀

- 技术知识、工程知识或设计模式：链接

## 我的收获

这次形成了什么可复用判断？以前的理解哪里需要修正？

## 后续

- [ ] 项目待办
- [ ] 个人知识待查证事项
```

## 为什么只做索引

同一事实写三遍，很快就会出现版本不一致：

- 项目实施事实和维护结论只写在项目仓库；
- 从真实工作中提炼的方法写入[工程知识](../工程知识/README.md)；
- 公开案例和资料形成[技术案例](../案例库/README.md)、[技术知识](../技术知识库/README.md)或[设计模式](../设计模式库/README.md)；
- 工作复盘只把这些内容连接起来，并记录个人反思。

目前还没有正式工作复盘。后续开始记录时，可以直接使用[工作复盘模板](../模板/工作复盘模板.md)。
