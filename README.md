# 我的工程知识库

这是我用来整理技术方案、工程经验、技术见闻和思考过程的地方。

我发现，工程工作很容易只留下最后的代码、参数或结果，却没有留下更重要的部分：当时遇到了什么问题，受到哪些约束，为什么选择这个方案，放弃了哪些路线，以及最后用什么证据判断它是否有效。

这个仓库希望把这些过程保存下来，让今天遇到的问题，能够成为以后处理新项目时可以复用的经验。

## 为什么建立这个知识库

随着参与的项目和涉及的技术方向不断增加，我逐渐遇到三个问题：

1. 个人记忆无法长期保存越来越多的技术知识、判断过程和项目经验，过去理解和使用过的内容很容易遗忘；
2. 项目文档分散在不同仓库中，难以从多个项目里汇集线索、比较做法并提炼可以复用的经验；
3. 很多有价值的想法散落在 AI 对话、阅读、讨论和随时产生的思考中，缺少统一入口，容易丢失。

因此，这个仓库不只是资料收藏夹，也不复制所有项目文档。它是一套个人工程认知系统：接收零散输入，连接项目事实，保留当时的判断过程，并把其中有长期价值的部分逐步沉淀为可复用知识。

## 最简单的使用方式

这个知识库由项目根目录的 [AGENTS.md](AGENTS.md) 定义“个人知识库管家”角色。进入本项目工作的 AI Agent 负责归纳、查重、放置、关联和维护[知识库索引](索引.md)，不把分类工作推给用户。

平时可以直接输入内容并说明“记下来”或“沉淀进知识库”。内容还不完整时，先进入[收件箱](收件箱/README.md)；已经具有明确上下文时，Agent 会搜索并更新最相关的已有文章。

```text
想法 / AI 对话 / 项目材料 / 外部资料
                  ↓
             交给 Agent
                  ↓
      查重、归纳、收录、关联、更新索引
```

记录时不要求选择目录、标签或成熟度。需要正式沉淀时，这些工作再由 Agent 完成。

## 这里会记录什么

### 案例库

保存一个完整技术问题是怎样被分析的：问题是什么、有哪些约束、考虑过哪些方案、为什么倾向某种架构、最大的风险在哪里。

案例可以来自公开规则、论文、产品、技术讨论，也可以来自经过脱敏的真实项目。

### 技术知识库

保存从案例和资料中提炼出的技术认识。例如某种定位方法解决什么问题、输入输出是什么、适合哪些场景、有什么代价，以及应该怎样验证。

### 设计模式库

保存可以跨项目复用的系统思想。这里不会只记录“用了什么型号”，而是总结为什么要这样分配计算、感知、估计和控制。

### 工程知识

保存我在真实工作中形成的工程方法和经验，例如故障诊断顺序、环境部署方法、日志分析方法、验证流程和常见误判。

具体项目里的设备编号、参数、配置、接线和修复记录仍然留在项目仓库。这里提炼的是以后还能继续使用的方法。

### 技术线索

暂存刚发现但还没有核实的论文、项目、视频、评论和陌生方案。它们完成查证后，才会进入正式的技术知识或案例。

### 工作复盘

作为日常工作的索引入口：链接具体项目文档，也链接从这项工作中产生的个人知识沉淀，避免同一内容重复写三遍。

## 仓库结构

```text
个人工程知识库/
├─ AGENTS.md        # 个人知识库管家的角色与工作规则
├─ 索引.md           # 由 Agent 维护的主要导航入口
├─ 收件箱/           # 零散输入和暂时无法分类的材料
├─ 案例库/           # 完整技术案例
├─ 技术知识库/       # 可跨项目复用的技术认识
├─ 设计模式库/       # 可复用的系统结构
├─ 工程知识/         # 从真实工作提炼的方法和经验
├─ 技术线索/         # 尚未核实的外部想法
├─ 工作复盘/         # 项目文档和个人沉淀的索引
├─ 模板/
└─ 资源/
```

## 这个仓库会怎样生长

```text
随手想法 / AI 对话 / 看到陌生方案
    ↓
交给 Agent，必要时先进入收件箱
    ↓
查重、归纳并保留来源与未知项
    ↓
查论文、官方资料、代码和实验
    ↓
形成技术知识，参与具体案例
    ↓
从多个案例或真实验证中总结设计模式

真实工作
    ↓
项目仓库记录具体事实
    ↓
这里提炼工程方法和个人经验
```

我希望这个仓库最终不只是“学过哪些知识”的清单，而是能够回答：

> 如果以后再次遇到类似问题，我应该先看什么、怎么判断、如何选择，以及怎样证明自己的方案真的有效？

## 如何理解文档状态

文档会使用 L0～L6 表示当前证据成熟度：

```text
L0 想法
L1 已调研
L2 已仿真
L3 已原型验证
L4 已真实场景测试
L5 可重复
L6 项目级或产品级
```

这个等级不是给内容“打分”，而是避免把“我听说过”“我查过资料”“我做过一次”和“已经稳定可靠”混在一起。

## 关于项目文档

项目仓库中的文档是 canonical documentation（规范主版本文档），负责保存需求、接口、配置、参数、部署、测试结果和维护事实。

这个个人知识库不会再复制一份项目文档，而是保存从项目中抽象出的原理、方法、经验、判断和复盘。需要具体事实时，应该通过链接回到对应项目仓库查看。

## 当前边界

- 英文缩写第一次出现时尽量补充中文解释。
- 没有一手来源或实验结果的内容明确标记为待核实、待验证。
- 不提交公司、客户、实验室或团队未公开资料。
- 不提交密钥、账号、内部网络信息和未经授权的源码或附件。
