# 无人机技术方案库

这是一个面向长期积累和检索的个人工程知识库。目录使用中文，专业缩写保留行业常用写法，并在正文第一次出现时补充中文名称和英文全称。

仓库当前以无人机和机器人系统为主要内容，但组织方式也适用于其他工程领域。

## 核心逻辑

```text
技术线索：我发现了什么？
    ↓ 查证
技术知识库：这个东西是什么？
    ↓ 用于项目
案例库：这个具体系统怎么做？
    ↓ 记录关键选择
架构决策记录：为什么这么选？
    ↓ 跨案例抽象
设计模式库：以后还能怎么复用？
```

## 目录

```text
无人机技术方案库/
├─ 案例库/                 # 一个具体系统如何设计和演进
├─ 技术知识库/             # 单项技术的原理、边界和工程特性
├─ 设计模式库/             # 可跨项目复用的系统思想
├─ 技术线索/               # 尚未查证、已验证或已否决的线索
├─ 模板/                   # 统一但不过度约束的记录模板
└─ 资源/                   # 架构图、图片、数据和附件
```

## 使用原则

### 先记录线索，再决定是否沉淀

刚看到的论文、视频、评论或方案先放入 `技术线索/待研究/`，保留来源和未知问题。完成查证后，再进入技术知识库、案例库或设计模式库。

### 区分来源、灵感和证据

受到某项技术启发，不代表新方案已被该技术验证。每篇记录应尽量说明：

- 原始来源是什么；
- 哪部分属于可核实事实；
- 哪部分是自己的推断；
- 哪部分已经实验验证；
- 哪些问题仍然不知道。

### 案例、知识和模式不要互相替代

- 案例库保留完整系统上下文和取舍过程。
- 技术知识库总结技术本身，不被某个项目绑死。
- 设计模式库抽象跨项目可复用的思想，也要写清适用边界和代价。

### 不提前制造空洞结论

本仓库中的“待整理”“待研究”“提议中”都表示内容尚未形成可靠结论。没有官方原文、原始数据或实验结果时，不写成已经确认的事实。

## 文件命名

- 目录使用简短中文名称。
- 文件名以中文为主，保留行业常用缩写，例如：
  - `ESKF误差状态卡尔曼滤波.md`
  - `VIO视觉惯性里程计.md`
  - `MAVLink通信协议.md`
  - `PX4飞控架构.md`
- 不使用过长目录名，避免路径难以阅读和维护。

## 公开边界

这是公开仓库。不要提交公司、客户、实验室或团队未公开资料，不要提交密钥、账号、内部网络信息、未经授权的源码、图片和聊天记录。引用第三方内容时优先链接原始来源，必要时进行匿名和脱敏处理。
