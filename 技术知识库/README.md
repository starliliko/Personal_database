# 技术知识库

这里整理那些离开某个具体项目以后，仍然值得保留的技术认识。

一篇技术知识不会只解释名词，也不会一开始就堆公式。它更关心工程决策：这项技术解决什么问题，需要什么输入，能够输出什么，适用于哪些场景，有什么代价，以及应该怎样证明它真的可用。

## 系统架构

### [外部感知与机载实时控制](系统架构/外部感知与机载实时控制.md)

当机器人本体的尺寸、重量、功耗和算力都很紧张时，可以把重传感器与复杂计算移到外部，把高频估计、实时控制和安全保护留在本体。

这篇文档总结了这种技术路线的基本分工、接口需求、适用条件、主要代价和验证路径。目前成熟度为 L0，来源是 RM2027 技术案例。

### [无人机自主定位系统的原型与产品化路线](系统架构/无人机自主定位系统的原型与产品化路线.md)

从成品飞控、伴随计算机和成品传感器开始，逐步建立 LIO/VIO 闭环基线、统一接口、半定制硬件、视觉惯性模块和产品级标定测试。重点是按验证门槛提高集成度，而不是过早把所有器件做成一体产品。

## 状态估计

### [无人机 VIO、LIO 与 PX4 状态估计的分层关系](状态估计/无人机VIO-LIO与PX4状态估计的分层关系.md)

区分传感器、里程计、飞控状态估计和控制的职责，整理多颗 IMU、外部里程计接口、多定位源相关性和分层验证方法。

### [多传感器融合中的时间戳、同步与延迟](状态估计/多传感器融合中的时间戳同步与延迟.md)

区分测量时间、到达时间、固定延迟、抖动和时钟偏移，说明时间错误怎样影响 VIO、LIO 和 PX4 外部观测融合，以及应该记录和验证什么。

## 传感器标定

### [无人机视觉惯性系统的内参与时空外参](传感器标定/无人机视觉惯性系统的内参与时空外参.md)

整理鱼眼相机内参、多相机外参、Camera–IMU 空间与时间外参、IMU 噪声模型，以及从原型手工标定走向可重复产品标定的要求。

## 技术选型

### [受限条件下的无人机定位方案选型](技术选型/受限条件下的无人机定位方案选型.md)

这篇文档整理了一套定位方案比较方法：先写规则、环境、重量、算力、延迟和安全约束，再比较光流、VIO、LIO、超宽带和外部定位，同时检查时间戳、标定与飞控接口。

重点不是得出一个永远正确的答案，而是建立可以复用的排除顺序、最小验证方法和常见误判清单。

## 后续会怎样扩展

当技术线索、案例或对话材料已经形成具有独立检索价值的问题、边界和验证路径时，可以在这里建立条目。证据不足的内容必须保持 L0 并明确待核实；完成一手资料、代码或实验查证后再提高成熟度。不会为了让目录显得丰富而提前建立大量空文件。

如果内容来自真实工作，具体参数和项目事实仍留在项目仓库；这里保存抽象后的技术能力与边界。
