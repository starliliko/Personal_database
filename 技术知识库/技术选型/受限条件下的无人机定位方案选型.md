# 受限条件下的无人机定位方案选型

- 当前成熟度：L0 想法
- 来源：从 RM2027 定位方案讨论，以及用户提供的 ChatGPT 对话“VIO LIO融合IMU”“解析无人机定位方案对比”中提炼

## 要解决的问题

面对重量、算力、规则、环境和实时性限制时，如何系统比较光流、视觉惯性导航、超宽带、外部视觉和外部激光雷达，而不是看到一个传感器就直接选型。

## 第一步：先写约束

至少明确：

- 规则允许和禁止什么；
- 目标环境是否有卫星定位、纹理、光照、可观测几何和外部基础设施；
- 尺寸、重量、功耗和算力预算；
- 定位精度、更新率、延迟和可用率；
- 遮挡、撞击、振动和通信中断等异常；
- 单机还是多机，是否需要身份关联。

不能确认的数据直接写“待确认”，不要用印象补齐。

## 第二步：明确需要观测什么

区分位置、速度、姿态、相对运动和目标身份。光流可以提供短时图像运动约束，但不自然等同于长期绝对位置；外部位置观测也不能自动解决高频姿态控制。

还要区分：

- 传感器原始测量；
- VIO 或 LIO 输出的局部里程计；
- 全局或场地绝对位置；
- PX4 EKF2 最终提供给控制器的飞行状态。

里程计连续、短时精度高，不代表长期无漂移；绝对位置长期有界，也不代表更新频率和延迟能够直接满足控制。

## 第三步：先做硬约束淘汰

例如：

- 规则明确禁止的方案直接淘汰；
- 超出重量、功耗或安装空间的方案直接淘汰；
- 无法满足场地覆盖的外部方案直接淘汰；
- 无法达到最低更新率或延迟要求的方案直接淘汰。

只有通过硬约束后，才比较精度、成本、开发难度和维护性。

## 第四步：比较方案的系统代价

| 方案类型 | 需要重点检查 |
| --- | --- |
| 机载光流 | 地面纹理、光照、高度、漂移和绝对位置来源 |
| 视觉惯性导航 | 相机与 IMU 同步、标定、纹理、光照、运动模糊、累计漂移和恢复能力 |
| 多鱼眼视觉惯性导航 | 多相机同步、鱼眼模型、相机间外参、图像带宽、遮挡与算法支持 |
| 机载激光惯性导航 | LiDAR 与 IMU 时间关系、几何退化、回波、运动去畸变、重量、功耗和算力 |
| 超宽带定位 | 规则、基站部署、非视距误差和多机容量 |
| 外部视觉 | 视场、远距离像素、遮挡、身份和标定 |
| 外部激光雷达 | 点密度、反射特性、视场、遮挡、误检和通信 |

### VIO、LIO 与外部定位的差异

| 维度 | VIO | LIO | 外部定位 |
| --- | --- | --- | --- |
| 主要环境约束 | 可观测纹理、光照和成像质量 | 可观测几何和可靠回波 | 外部设施覆盖、遮挡和通信 |
| 主要工程负担 | 相机带宽、曝光、鱼眼模型和时空标定 | 雷达重量、功耗、点云计算和去畸变 | 场地标定、目标识别、身份关联和链路延迟 |
| 典型优势 | 轻量、语义信息丰富、易扩展大视场 | 三维尺度直接、弱光可用、几何测量强 | 减少机载传感器与计算负担 |
| 典型退化 | 低纹理、模糊、过曝、滚动快门 | 长走廊、平面、玻璃、弱回波 | 视场死角、遮挡、共同故障点 |

不能笼统地说 LIO“不依赖环境”。VIO 依赖视觉可观测性，LIO 依赖几何与回波可观测性，二者只是退化条件不同。

## 第五步：检查时间、标定与接口

传感器选型不仅看精度、分辨率和视场角，还要核对：

- 相机或激光雷达是否具有时间关系明确的 IMU；
- 时间戳代表测量时刻还是主机接收时刻；
- 是否支持硬件触发、统一时钟或可验证的时钟映射；
- 相机内参、鱼眼模型、传感器间外参和时间偏移怎样获得；
- 里程计怎样表达坐标系、协方差、重置和健康状态；
- PX4 所用版本怎样接收、延迟补偿和拒绝外部观测。

## 第六步：先做最小验证

- 用场地图片或实测数据检查光流和视觉条件；
- 根据距离和视场计算目标像素或激光雷达点数；
- 测量真实链路延迟，而不是只看接口标称值；
- 分别记录设备采样、主机接收、算法输出和飞控接收时间；
- 在相同轨迹和环境下比较 VIO、LIO 或外部定位，而不是比较不同演示条件；
- 先验证最可能推翻方案的风险；
- 设定通过和失败判据；
- 将结果写回项目仓库，个人库只保留可复用的方法和结论。

## 常见误判

- 把某块测试地面的效果推广到整个场地；
- 把论文中的识别方法直接当成当前系统可行性证明；
- 只看传感器精度，不看更新率、延迟、遮挡和故障恢复；
- 只计算核心板重量，遗漏供电、散热、外壳、线缆和安装结构；
- 先选算力平台，再测实际负载；
- 把“能收到数据”当成“能进入控制闭环”。
- 把消息到达时间当成传感器测量时间；
- 认为 VIO、LIO 和外部定位同时输入就自然形成可靠冗余；
- 只检查轨迹是否平滑，不检查坐标系、协方差、重置和失效恢复；
- 把一体化传感器理解为已经替用户解决全部同步与标定问题。
