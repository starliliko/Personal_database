# 受限条件下的无人机定位方案选型

- 当前成熟度：L0 想法
- 来源：从 RM2027 定位方案讨论中提炼

## 要解决的问题

面对重量、算力、规则、环境和实时性限制时，如何系统比较光流、视觉惯性导航、超宽带、外部视觉和外部激光雷达，而不是看到一个传感器就直接选型。

## 第一步：先写约束

至少明确：

- 规则允许和禁止什么；
- 目标环境是否有卫星定位、纹理、光照和外部基础设施；
- 尺寸、重量、功耗和算力预算；
- 定位精度、更新率、延迟和可用率；
- 遮挡、撞击、振动和通信中断等异常；
- 单机还是多机，是否需要身份关联。

不能确认的数据直接写“待确认”，不要用印象补齐。

## 第二步：明确需要观测什么

区分位置、速度、姿态、相对运动和目标身份。光流可以提供短时图像运动约束，但不自然等同于长期绝对位置；外部位置观测也不能自动解决高频姿态控制。

## 第三步：先做硬约束淘汰

例如：

- 规则明确禁止的方案直接淘汰；
- 超出重量、功耗或安装空间的方案直接淘汰；
- 无法满足场地覆盖的外部方案直接淘汰；
- 无法达到最低更新率或延迟要求的方案直接淘汰。

只有通过硬约束后，才比较精度、成本、开发难度和维护性。

## 第四步：比较方案的系统代价

| 方案类型 | 需要重点检查 |
| --- | --- |
| 机载光流 | 地面纹理、光照、高度、漂移和绝对位置来源 |
| 视觉惯性导航 | 重量、功耗、纹理、运动模糊、累计漂移和恢复能力 |
| 超宽带定位 | 规则、基站部署、非视距误差和多机容量 |
| 外部视觉 | 视场、远距离像素、遮挡、身份和标定 |
| 外部激光雷达 | 点密度、反射特性、视场、遮挡、误检和通信 |

## 第五步：先做最小验证

- 用场地图片或实测数据检查光流和视觉条件；
- 根据距离和视场计算目标像素或激光雷达点数；
- 测量真实链路延迟，而不是只看接口标称值；
- 先验证最可能推翻方案的风险；
- 设定通过和失败判据；
- 将结果写回项目仓库，个人库只保留可复用的方法和结论。

## 常见误判

- 把某块测试地面的效果推广到整个场地；
- 把论文中的识别方法直接当成当前系统可行性证明；
- 只看传感器精度，不看更新率、延迟、遮挡和故障恢复；
- 只计算核心板重量，遗漏供电、散热、外壳、线缆和安装结构；
- 先选算力平台，再测实际负载；
- 把“能收到数据”当成“能进入控制闭环”。
