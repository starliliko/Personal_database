# 从激光建图定位到 PX4 闭环的无人机系统路线

- 当前成熟度：L1 项目证据支持的架构总结
- 来源：用户确认的既往无人机项目，以及对其私有项目资料的脱敏核对
- 记录日期：2026-09-11
- 适用范围：使用三维激光雷达、惯性测量单元（IMU）、ROS 2、伴随计算机和 PX4 的室内无人机
- 公开边界：不公开私有项目仓库、完整源码、内部路径、设备身份、网络配置、CAD/EDA 原文件、原始日志和未经确认的参数

## 要解决的问题

在无卫星定位的室内环境中，无人机需要持续得到低延迟、方向正确且足够稳定的位置、速度和姿态，才能完成定点悬停和轨迹飞行。单独让激光里程计在可视化界面中输出轨迹并不足够，还必须打通建图、地图定位、坐标转换、飞控融合、控制准入和日志验收。

本文描述一条经过真实项目支撑的通用路线，但不复制具体项目实现。

## 总体架构

```text
三维激光雷达 + IMU
        ↓
驱动与测量时间戳
        ↓
激光惯性里程计（LIO）
        ↓
局部连续位姿 ────────────────┐
        ↓                     │
增量建图                     │
        ↓                     │
回环与位姿图优化             │
        ↓                     │
地图精化与保存               │
        ↓                     │
基于已有地图的全局重定位 ────┘
        ↓
连续的地图坐标系里程计
        ↓
时间、坐标系和不确定度转换
        ↓
PX4 外部里程计观测
        ↓
PX4 EKF2 状态估计
        ↓
悬停、路径跟随与安全降级
```

这条路线可以拆成“建图”“定位”“飞控融合”和“控制”四个阶段。拆分的好处是每一层都能独立验收，失败时也容易判断问题属于传感器、算法、接口、估计器还是控制器。

## 阶段一：激光惯性里程计与建图

### 基本处理链

1. 激光雷达输出点云，IMU 输出角速度和比力。
2. IMU 在两帧点云之间进行高频状态传播。
3. 根据点的采样时刻进行点云运动补偿，避免无人机运动把一帧点云拉扭。
4. 将当前点云与局部地图建立几何约束。
5. 通过迭代滤波修正位置、姿态、速度、重力方向和 IMU 零偏。
6. 输出局部连续里程计，并把新的有效点插入增量地图。

FAST-LIO2 属于这类紧耦合激光惯性里程计。它提供高频局部状态和增量地图，但局部连续并不自动代表长时间全局一致。

### 回环与地图优化

如果任务需要较大场地或重复经过相同区域，可以增加：

- 回环检测：识别当前区域是否曾经访问；
- 位姿图优化（PGO）：使用回环约束重新调整历史位姿；
- 地图一致性优化：进一步减少点云重影和局部拼接误差；
- 地图保存：输出供后续定位使用的 PCD 等地图文件。

回环和地图优化主要改善全局一致性，不应放进飞行控制的高频关键路径。即使优化过程暂时中断，局部里程计仍应能够维持连续输出。

## 阶段二：基于已有地图的定位

建图完成后，后续飞行可以加载已有地图进行定位：

```text
实时点云 + IMU
      ↓
高频局部 LIO
      ↓
当前扫描与已有地图进行 ICP 匹配
      ↓
得到 map → odom 的低频全局修正
      ↓
融合局部连续运动和全局修正
      ↓
输出 map 坐标系下的连续里程计
```

这里有两类不同频率的信息：

- 局部 LIO 高频、连续，适合控制，但会缓慢漂移；
- 全局地图匹配频率较低，能够修正漂移，但可能出现错误匹配或跳变。

工程上不应直接把低频全局匹配结果当作高频控制状态。更合理的做法是估计 `map → odom` 修正，再与连续的 `odom → body` 组合，既保留控制连续性，又逐步消除全局漂移。

### 初始重定位

地图定位通常需要一个大致初始位姿，或者使用全局描述子完成候选区域搜索。初值错误时，迭代最近点（ICP）可能收敛到错误的局部最优解。

进入飞控融合前至少检查：

- 匹配适应度或残差；
- 当前点云与地图的有效重叠比例；
- 位姿跳变量；
- 连续多次匹配是否一致；
- 地图版本是否与当前场地一致；
- 失败后是否停止发布有效定位，而不是继续输出看似正常的数据。

## 阶段三：转换为 PX4 可以融合的外部里程计

定位算法输出通常是 ROS 2 `nav_msgs/Odometry` 或 TF，而 PX4 需要符合自身坐标、时间和消息语义的外部里程计观测。

转换层至少负责：

| 项目 | 必须明确的内容 |
| --- | --- |
| 测量时间 | 使用传感器对应的采样时刻，不把节点发送时刻冒充测量时刻 |
| 世界坐标系 | ROS 常用 ENU，PX4 常用 NED，必须显式转换 |
| 机体坐标系 | ROS 常用 FLU，PX4 常用 FRD，必须显式转换 |
| 姿态方向 | 明确四元数表示的是父系到子系还是子系到父系 |
| 位置与速度 | 说明分别在哪个坐标系中表达，不能只转换位置 |
| 协方差 | 应反映实际误差或健康度，不能长期填写过度乐观的固定值 |
| 重置 | 定位重启、回环修正和重新定位需要携带重置或连续性信息 |
| 健康状态 | 输入超时、冻结、跳变和地图匹配失败时必须停止宣称有效 |

### 脱敏后的接口示意代码

下面是重新编写的结构示意，不是私有项目源码，也不包含项目参数：

```cpp
void OdometryBridge::onOdometry(const nav_msgs::msg::Odometry& input)
{
    if (!timestampIsValid(input.header.stamp) ||
        !poseIsFinite(input.pose.pose) ||
        !sourceIsHealthy()) {
        markExternalOdometryUnavailable();
        return;
    }

    const Pose ned_pose = convertEnuFluToNedFrd(input.pose.pose);

    px4_msgs::msg::VehicleOdometry output{};
    output.timestamp_sample = toMicroseconds(input.header.stamp);
    output.position = ned_pose.position;
    output.q = ned_pose.orientation;
    output.position_variance = estimatePositionVariance(input);
    output.orientation_variance = estimateAttitudeVariance(input);
    output.reset_counter = resetCounter();
    output.quality = currentQuality();

    publisher_->publish(output);
}
```

示例故意没有给出具体话题、固定方差、坐标矩阵或项目类名。真正实现时，应通过静止、单轴平移、单轴旋转和组合运动验证每一个坐标方向，而不是只凭公式判断转换正确。

### 为什么消息名里可能仍有 Visual Odometry

某些 PX4 版本或接口沿用 `vehicle_visual_odometry` 名称接收外部里程计。消息名称中的“视觉”不代表数据必须来自相机；能否用于激光里程计取决于该版本的接口定义、EKF2 配置和消息字段语义，必须按实际固件版本核对。

## 阶段四：飞控融合与控制准入

PX4 EKF2 使用飞控本地 IMU 进行高频传播，把外部里程计作为位置、速度或姿态观测进行校正。LIO 不直接控制电机，控制器使用的是飞控最终接受并融合后的状态。

闭环前需要检查：

1. 外部里程计是否真正进入飞控，而不只是 ROS 2 端可以看到话题；
2. EKF2 是否接受观测，有没有持续拒绝或超时；
3. 创新量和创新检验比是否健康；
4. 本地位置是否有效、连续，是否发生非预期复位；
5. 定位中断时控制器是否保持、降落或交还人工控制；
6. 重新定位产生大跳变时，控制器是否会追逐错误目标。

### 控制准入示意

下面同样是通用伪代码，不是私有项目源码：

```cpp
if (!local_position_valid || odometry_timed_out) {
    goto_enabled = false;
    requestSafeHoldOrLand();
}

if (operator_enable && flight_state == HOVER && local_position_valid) {
    goto_enabled = true;
}

if (goto_enabled && targetIsFinite(command) && !commandTimedOut()) {
    publishTrajectorySetpoint(command);
} else {
    holdCurrentPosition();
}
```

这里的核心不是按键或状态名称，而是三条原则：

- 外部目标必须经过准入；
- 定位健康是继续执行目标的必要条件；
- 超时、无效数值和模式退出必须回到确定的安全状态。

## 建图、定位、规划和控制的边界

| 模块 | 主要输入 | 主要输出 | 不负责什么 |
| --- | --- | --- | --- |
| LIO | 点云、IMU | 局部连续里程计、增量地图 | 不直接控制电机 |
| PGO/HBA | 历史位姿、点云、回环 | 全局更一致的地图 | 不提供控制所需的最高频状态 |
| 地图定位 | 当前点云、局部里程计、已有地图 | 地图坐标系位姿修正 | 不负责飞控模式与安全状态 |
| 里程计转换 | ROS 2 位姿、时间和质量 | PX4 外部里程计消息 | 不应伪造定位质量 |
| PX4 EKF2 | 飞控 IMU、外部里程计等 | 飞行控制状态 | 不负责建图和路径规划 |
| 路径模块 | 地图、航点或记录路径 | 连续目标或航点 | 不直接绕过控制准入下发电机量 |
| 控制模块 | 当前状态、目标和安全条件 | PX4 轨迹设定值或模式命令 | 不应在定位失效时盲目执行目标 |

## 分层验收方法

### 第 1 层：原始传感器

- 点云和 IMU 持续更新；
- 频率和时间戳连续；
- 每点时间信息满足运动补偿需求；
- 静止时 IMU 无明显异常；
- 传感器重连不会留下旧数据。

### 第 2 层：LIO

- 静止时位置和姿态不持续发散；
- 平移、旋转方向与实物一致；
- 快速转动时点云没有明显撕裂；
- 外参和时间偏移经过验证；
- 退化环境能够被检测。

### 第 3 层：地图与重定位

- 地图无严重重影；
- 回环前后轨迹修正合理；
- 重定位不会稳定地落在错误区域；
- 地图不匹配时能拒绝结果；
- 重定位修正不会直接制造控制跳变。

### 第 4 层：ROS 2 到 PX4

- 消息时间单调；
- 采样时间和发送时间没有混淆；
- 坐标轴方向逐轴验证；
- PX4 内部能够持续收到消息；
- 固定延迟、抖动、丢包和冻结有统计数据。

### 第 5 层：EKF2

- 融合标志符合预期；
- 创新量健康；
- 外部观测没有被长期拒绝；
- 状态重置计数和位置跳变可解释；
- 协方差与实际误差大致一致。

### 第 6 层：闭环飞行

- 先拆桨、地面移动，再系留或保护条件下飞行；
- 先定高，再定点，再低速轨迹；
- 保存机体版本、参数、软件提交和飞行日志；
- 注入定位超时、冻结和重定位跳变；
- 验证人工接管、保持和降落逻辑。

## 项目经验中暴露的典型风险

### 把发布频率当成新观测频率

定时器可以把输出发布到更高频率，但重复传播或重复发送并不会产生新的环境观测。必须区分传感器采样频率、算法更新频率、消息发布频率和飞控实际接受频率。

### 固定协方差和固定质量值

固定填写很小的方差，会使飞控在定位已经退化时仍然过度相信外部观测。质量应至少随匹配残差、有效点数、时间延迟和重定位状态变化。

### 到达时间冒充测量时间

ROS 2 节点收到消息或发布结果的时刻不等于激光点和 IMU 被采样的时刻。高动态飞行中，几毫秒偏差就可能变成明显姿态和位置误差。

### 路径、规划和控制耦合过深

路径模块应输出目标，控制模块负责准入、限幅和失效处理。规划器不应绕过安全状态机直接向飞控发送未经检查的目标。

### 配置绑定绝对路径和设备编号

原型中常见的绝对路径、临时串口名和固定网卡名会降低第二台设备的可复现性。产品化需要稳定设备身份、相对配置入口、版本化参数和逐机验收。

## 迁移到多目 VIO 时可以复用什么

从 LIO 切换到四路鱼眼加两个下视摄像头的视觉惯性里程计（VIO）后，下游架构基本可以保留：

```text
多路图像 + IMU
      ↓
多目 VIO
      ↓
统一里程计接口
      ↓
坐标、时间与不确定度转换
      ↓
PX4 EKF2
      ↓
控制准入、悬停和轨迹
```

可以复用：

- ROS 2 模块化组织；
- 外部里程计接口；
- PX4 通信与 EKF2 验收；
- 控制状态机；
- 路径记录和跟随；
- 飞行日志分析；
- 分层调试和故障注入方法。

需要重新解决：

- 鱼眼成像模型和各相机内参；
- 六相机空间外参；
- Camera–IMU 空间和时间外参；
- 六路曝光与硬件同步；
- 运动模糊、低纹理、低照度和重复纹理；
- 多路图像带宽与算力；
- 视觉退化时的质量估计和降级。

## 公开代码边界

可以公开：

- 重新编写的架构示意和伪代码；
- 基于 ROS 2/PX4 公共消息定义的最小接口示例；
- 不含项目参数的坐标转换测试方法；
- 通用状态机、超时检查和故障注入方法；
- 从项目中抽象出的错误模式和验收清单。

不应公开：

- 私有仓库地址和内部目录结构；
- 成套复制的核心飞控、转换、控制和规划源码；
- 私有 CAD、EDA、固件、地图、飞行日志和数据集；
- 内部设备身份、网络地址、账号和部署路径；
- 未确认授权的第三方源码及其本地修改；
- 仅从私有项目中才能识别的产品和组织信息。
